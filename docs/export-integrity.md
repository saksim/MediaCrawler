# 文件导出约定

JSON 追加在同目录临时文件中完成序列化、写入、flush/fsync，再用原子替换更新目标文件。
序列化、写入或替换失败时保留原文件；遇到无法解析的已有 JSON 会抛出异常，供用户检查和恢复，
不再自动清空历史结果。所有 writer 对同一路径的读改写共享锁，取消时等线程 I/O 完成再释放锁。
CSV/JSON/JSONL 都按文件串行化，兼容工厂为每条记录创建新 writer 的调用方式。
这是进程内保证；不同进程不能同时追加同一个输出文件。大量采集优先选择默认 JSONL，
因为 JSON 数组每次追加仍需读写整个文件。

CSV 以已有文件的表头为 schema；字段顺序改变时按名字映射，缺字段留空。
出现新字段会在追加前明确报错，请选择新输出文件或做显式 schema 迁移。
Excel 保留原表头顺序，新增字段追加到右侧，历史行对应单元格为空。

Excel 中的字符串存为文本类型。CSV 对可能被表格软件识别为公式的字符串前置单引号，
包括 `= + - @` 和危险前导空白；实际数值不受影响。需要原始文本时使用 JSON/JSONL。
这不会修复已导出的旧文件，也不保证用户去掉转义后再次打开仍然安全。
